# Working with this repository

Build the film the user wants. The tools support creative judgment; the docs are
working knowledge, not a mandatory production ceremony. Use the guidance that
helps the current project and leave the rest alone.
Read any private profile's linked instructions for the user's current preferences;
their latest explicit direction takes precedence over older project guidance.
Linked instructions are the private files a profile lists under `instructions`;
a profile without them, or no profile at all, is normal.

- Keep private productions separate from this public code checkout. Resolve
  project paths and account settings explicitly; examples grant no authority.
- Preserve source files and useful provenance. Record what was actually generated,
  inspected, or approved without inventing a user verdict.
- Respect the user's spending and publication scope. Use resumable finite jobs
  and persisted provider task IDs to avoid duplicate charges after interruption.
- Run heavy production on configured GPU workers. The coordinator handles
  orchestration, metadata, transfer, and reviews.
- Prefer a small improvement in an existing module over another layer. Keep
  temporary exploration outside Git. Do not add AI-authorship signatures.

[Workflow](docs/WORKFLOW.md) maps the available tools. Consult
[configuration](docs/CONFIGURATION.md) for paths and credentials,
[integrity](docs/INTEGRITY.md) for technical contracts, and
[workers](docs/WORKERS.md) for runtime setup. [Creative](docs/CREATIVE.md) and
[sound](docs/SOUND.md) notes are optional starting points, not templates or gates.
